## 目录说明（OpenMCP Client）

本文档用于帮助快速理解仓库的目录结构与各模块职责。仓库是一个 Turbo 管理的多包（monorepo）项目，核心关注点是：**VSCode 扩展（`src/`）**、**后端服务（`service/`）**、**前端渲染（`renderer/`）**，以及围绕它们的 **SDK / Gateway / CLI**。

---

## 顶层结构总览

下面是顶层目录的“按重要性分组”说明（不追求逐文件罗列）：

- **核心模块**
  - `src/`：VSCode Extension 主代码（扩展入口与 webview 侧桥接）。
  - `service/`：Node.js 后端服务层（MCP 连接、路由、控制器等）。
  - `renderer/`：Vue 前端渲染层（面板 UI、消息桥接等）。
  - `sdk/`：面向业务/集成方的 TypeScript SDK（供外部或内部调用）。
  - `gateway/`：网关/转发层（通常用于把某些能力封装成独立进程/服务入口）。
  - `cli/`：命令行工具（开发/运维/脚本化场景使用）。
  - `test/`：测试用例与测试夹具（含 SDK 相关测试）。

- **构建与发布相关**
  - `dist/`：根包构建产物（不同命令可能生成不同内容）。
  - `scripts/`：发布、资源准备、调试等脚本集合。
  - `.github/`：CI/CD、Issue/PR 模板等 GitHub 配置。
  - `.vscode/`：工作区 VSCode 配置。
  - `.turbo/`、`turbo.json`：Turbo 任务编排与缓存目录。

- **资源与多语言**
  - `resources/`：OCR / SDK release 等资源文件。
  - `icons/`：图标资源。
  - `l10n/`：本地化资源（多语言）。
  - `news/`：新闻/公告数据（用于 UI 展示或更新机制）。

- **其它**
  - `servers/`：示例/配套服务器（当前看起来包含 Python 项目）。
  - `software/`：第三方软件/依赖相关内容（通常用于打包或离线依赖）。
  - `node_modules/`：依赖安装产物（本目录在 CI/发布产物中通常不提交/不依赖）。

---

## 重点目录详解

### `cli/`（命令行工具）

用于提供命令行入口，便于脚本化调用、开发调试或运维场景执行特定操作。

常见子目录：

- `cli/src/`：源码
  - `cli/src/commands/`：命令定义（通常一条命令对应一个文件/模块）
  - `cli/src/lib/`：CLI 共享工具函数/封装
  - `cli/src/index.ts`：CLI 入口（命令注册、参数解析等）
- `cli/dist/`：构建产物
- `cli/bin/`：可执行入口脚本（如 node shebang 包装等）
- `cli/package.json`：CLI 包的依赖与脚本

---

### `gateway/`（网关层）

用于承载“网关/转发/聚合”类能力：把一些运行时能力包装成独立的入口（例如一个 `main.ts` 启动的服务进程），对外提供更稳定的调用方式。

常见子目录：

- `gateway/src/`
  - `gateway/src/main.ts`：网关进程入口（启动、监听、转发等主流程）
  - `gateway/src/index.ts`：对外导出的库入口（供其它包引用）
- `gateway/scripts/`：网关相关脚本
- `gateway/dist/`：构建产物
- `gateway/task-loop.d.ts`：与 task-loop 相关的类型声明（供 TS 使用）

---

### `sdk/`（TypeScript SDK）

面向“集成方/调用方”的 SDK 包，一般承载：

- 对外暴露稳定 API（隐藏内部通信细节）
- 类型声明、适配层、轻量的运行时代码
- 与 `service/` 或 `gateway/` 的协议/消息模型对齐

常见子目录：

- `sdk/src/`
  - `sdk/src/index.ts`：SDK 对外出口
  - `sdk/src/hook/`：与 hook/插件式能力相关的封装
- `sdk/scripts/`：构建或复制类型声明等脚本
- `sdk/dist/`：构建产物
- `sdk/rollup.config.js`：SDK 打包配置（便于发布为更兼容的产物）

---

### `service/`（服务层 / Node.js 后端）

后端服务层通常负责：

- MCP 连接与管理（多连接、重连、不同 transport 抽象等）
- 请求路由与控制器（把前端/扩展侧请求转为具体执行）
- 与 LLM、技能、设置、面板等模块的聚合

常见子目录（按领域划分）：

- `service/src/common/`：通用工具、路由、基础设施
- `service/src/mcp/`：MCP 相关核心逻辑（连接、客户端、协议适配等）
- `service/src/llm/`：LLM 相关能力（对话、工具调用编排等）
- `service/src/setting/`：设置与配置管理
- `service/src/panel/`：面板/界面相关的服务端支撑
- `service/src/cloud/`：Cloud/HTTP 对接层（后端 API 适配与鉴权上下文）
- `service/src/debugger-mcp/`：调试器 MCP 相关模块
- `service/src/hook/`：hook/插件机制
- `service/src/main.ts`：服务启动入口
- `service/src/index.ts`：对外导出（被其它包引用时使用）
- `service/dist/`：编译后的产物
- `service/task-loop.d.ts`：task-loop 相关类型声明

---

### `src/`（VSCode Extension 主代码）

这是 VSCode 扩展的核心代码目录，职责通常包括：

- 扩展激活与命令注册
- 与 `service/` 的启动/通信（或与 webview 的消息桥接）
- webview 生命周期管理与资源加载

常见子目录：

- `src/extension.ts`：扩展入口（activate/deactivate、注册命令等）
- `src/webview/`
  - `src/webview/webview.service.ts`：webview 服务（创建、更新、消息转发）
  - `src/webview/webview.controller.ts`：webview 控制器（路由/事件处理）
- `src/common/`：扩展侧通用工具
- `src/i18n/`：扩展侧国际化
- `src/sidebar/`：侧边栏相关实现
- `src/hook/`：扩展侧 hook/插件能力
- `src/test/`：扩展侧的测试/辅助测试代码

---

### `test/`（测试）

用于存放仓库级测试与夹具，按子项目拆分：

- `test/sdk/`：SDK 测试
  - `test/sdk/src/`：SDK 测试代码
  - `test/sdk/fixtures/`：测试夹具（模拟数据、样例项目等）
- `test/app/`：应用/集成测试（如果有 UI 或端到端测试，通常在这里）

---

## 其它目录（简要）

- `renderer/`：前端渲染（Vue + Vite），负责 UI 面板、交互与消息桥接；也会有自己的 `src/`、`public/`、`dist/`。
- `openmcp-sdk/`：已构建/发布形态的 SDK 产物目录（包含 `index.js`/`index.d.ts` 等），更偏“产物与分发”而非日常开发源码，不应该直接修改。
- `servers/`：配套/示例服务器（当前包含 Python 的 `pyproject.toml`、`uv.lock` 等），用于演示或本地联调。
- `resources/`：OCR 资源与 SDK release 资源（打包/运行时依赖）。
- `scripts/`：仓库级脚本（发布、资源准备、数据更新、调试等）。

---

## 阅读建议

- 想理解扩展是如何启动与如何打开 UI：从 `src/extension.ts` 与 `src/webview/` 开始。
- 想看 MCP 连接/协议/请求如何走：从 `service/src/mcp/` 与 `service/src/common/`（路由）开始。
- 想给外部项目集成调用：优先看 `sdk/src/index.ts`（对外 API）。
